# PadExtend 传输协议 v1（原型阶段）

> 阶段二原型协议。仅用于验证 USB（ADB 转发）通道连通性、数据完整性、序号校验与断线重连。
> 不是最终视频传输协议；后续阶段接入 H.264 帧时会在此基础上扩展 type。

## 帧格式（大端 / Big-Endian）

| 偏移 | 长度 | 字段   | 说明                                  |
|------|------|--------|---------------------------------------|
| 0    | 4    | magic  | 固定 ASCII `PEX1`（0x50 0x45 0x58 0x31）|
| 4    | 4    | seq    | uint32，发送端序号，从 0 递增          |
| 8    | 4    | type   | uint32，消息类型                       |
| 12   | 4    | length | uint32，payload 字节数                 |
| 16   | N    | payload| 具体内容，长度 = length                |

## type 取值

| type | 含义      | payload                          |
|------|-----------|----------------------------------|
| 1    | 文本消息  | UTF-8 文本                        |
| 2    | JPEG 图像 | 一张 JPEG 图片的原始字节          |

## 接收端校验规则

1. 读满 16 字节头，校验 magic == `PEX1`，否则判为流错位，断开重连。
2. 记录上一次 seq，若本次 seq != 上次 + 1（首包除外）记为“序号跳变/丢包”，计数并继续。
3. 按 length 读满 payload 再处理，读不满（连接断）则触发重连。
4. length 设上限（原型设 16 MB）防止异常头导致超大分配。

## 传输通道（原型）

- Windows 端：TCP 监听 `127.0.0.1:<PORT>`。
- Android 端：连接 `127.0.0.1:<PORT>`。
- 通过 `adb reverse tcp:<PORT> tcp:<PORT>` 把手机端口经 USB 转发到 PC。
- 默认 PORT = 27555。

## 断线重连

- 接收端连接失败或读到 EOF，等待 1 秒后重试，无限重连。
- 发送端为长连接服务器，接受客户端重新接入后从当前 seq 继续发。

## 阶段四扩展：H.264 视频帧（协议 v1.1）

> 在 v1 帧结构（PEX1 头 + seq + type + length + payload）之上新增视频 type。
> 头格式不变（大端）。新增 type 向后兼容：旧接收端遇到未知 type 应跳过 payload。

### 新增 type 取值

| type | 含义         | payload                                             |
|------|--------------|-----------------------------------------------------|
| 3    | H.264 配置   | codec 私有数据：SPS+PPS（Annex-B，含 00 00 00 01 起始码）|
| 4    | H.264 关键帧 | 一个 IDR 帧的 Annex-B NAL 单元                        |
| 5    | H.264 非关键帧 | 一个 P 帧的 Annex-B NAL 单元                        |
| 6    | 视频元信息   | JSON（UTF-8）：{"w":宽,"h":高,"fps":帧率}             |

### 约定

- 编码格式：H.264 (AVC)，Baseline/Main/High 均可，Annex-B 字节流（起始码分隔）。
- 发送顺序：连接建立后先发 type=6 元信息 → type=3 配置(SPS/PPS) → 之后持续发 type=4/5 帧。
- 每次新客户端接入都重发一次 type=6 + type=3，保证解码器可随时初始化。
- 关键帧（IDR）至少每 2 秒发一次，便于断线重连后快速恢复画面。
- 接收端（Android）用 MediaCodec 以 video/avc 配置：
  - 收到 type=3：作为 csd-0 送入 MediaFormat。
  - 收到 type=4/5：作为一个输入缓冲区送入解码器，输出渲染到 SurfaceView。

### 兼容性

- type=1(文本)/type=2(JPEG) 仍保留：原型回归测试与降级显示可用。
- 新 Android 客户端优先走 H.264(type=3/4/5)；若长时间只收到 type=2 则按 MJPEG 回退显示。
